# Розробка та перевірки

## Локальний запуск

Використовуйте npm і Node.js, сумісний із `engines` установлених залежностей;
проєкт перевірявся на Node.js 24.3. Версії пакетів зафіксовані lock-файлом.

```sh
npm ci
npm run dev
```

Адреса за замовчуванням — `http://127.0.0.1:3000`, не `localhost`.
`dev` і `start` прив’язують сервер до loopback. При іншому порті змініть також
`APP_ORIGIN` і повторно підключіть Сільпо; не запускайте другу копію на зайнятому
порті без перевірки вже запущеного процесу.

Потрібні параметри наведено в [.env.example](../.env.example). Наявний `.env`
зберігайте локально; не перезаписуйте ключ під час налаштування.

| Змінна           | Значення                                                                              |
| ---------------- | ------------------------------------------------------------------------------------- |
| `OPENAI_API_KEY` | Серверний ключ для створення плану й smoke-тесту                                      |
| `OPENAI_MODEL`   | Необов’язковий override; без нього модель обирає встановлений SDK                     |
| `APP_ORIGIN`     | Точний origin UI, Origin-перевірки та OAuth callback; default `http://127.0.0.1:3000` |

Для локальної production-перевірки: `npm run build`, потім `npm start`.
OAuth-токени не переживають перезапуск сервера. Сторінку й unit-тести можна
перевіряти без живого підключення OpenAI/Сільпо.

## Стиль і залежності

- [Prettier](../prettier.config.js): одинарні лапки, крапки з комою, 2 пробіли,
  ширина 80, LF, trailing commas. [Ignore](../.prettierignore) виключає секрети,
  кеші, generated-файли, lock-файл та агентські інструкції.
- [ESLint](../eslint.config.mjs): Next.js core-web-vitals, TypeScript,
  Prettier, simple-import-sort і правила perfectionist із `mf-project`.
  `lint` має `--max-warnings=0`.
- `typescript` — npm alias до API `@typescript/typescript6`, потрібного
  typescript-eslint; `@typescript/native` — alias до TypeScript 7 із binary
  `tsc`. Не замінюйте цю пару одним пакетом без перевірки сумісності.
- `@/` означає `src/`. Серверні модулі інтеграцій використовують `server-only`.
- Компоненти Home зберігайте презентаційними; API-запити та бізнес-логіку
  не дублюйте всередині карток результату.

## Команди

| Команда                | Призначення                                                              |
| ---------------------- | ------------------------------------------------------------------------ |
| `npm run lint`         | Перевірка JS/TS без виправлень                                           |
| `npm run lint:fix`     | Автовиправлення lint-правил і форматування JS/TS                         |
| `npm run format`       | Форматування всіх підтримуваних неігнорованих файлів                     |
| `npm run format:check` | Перевірка форматування без змін                                          |
| `npm run typecheck`    | `tsc --noEmit`, без мережевих запитів                                    |
| `npm test`             | `tsx --test tests/*.test.ts`, локальні синтетичні fixtures               |
| `npm run build`        | Production-збірка Next.js; не замінює запуск ESLint                      |
| `npm run smoke:openai` | Платний реальний запит: арифметичний tool і structured output, без Silpo |

Для точкового форматування: `node node_modules/prettier/bin/prettier.cjs --write docs/architecture.md`.
`AGENTS.md` навмисно ігнорується загальним форматуванням; для явної перевірки
можна передати його в Prettier через stdin з `--stdin-filepath AGENTS.md`.

локальні посилання й відповідність описів коду, без зайвих платних запитів.

## Жива перевірка і діагностика

1. Відкрийте локальний UI, підключіть Сільпо, пройдіть вхід і OAuth consent
   у браузері. Не копіюйте паролі, callback codes або cookies у чат/fixtures.
2. На сайті Сільпо налаштуйте кошик із магазином/доставкою та доступним слотом.
3. Введіть «Лазанья», 4 людини, 600 грн. Перевірте рецепт, посилання,
   фасування, кількості, суму та правдивість статусу. 600 грн не гарантовано.
4. Зафіксуйте, що саме перевіряли й коли; ціни та доступність залежать від слота.

`connected: true` означає лише наявність access token у сесії. Це не перевірка
чинності токена або кошика. `AUTH_REQUIRED` потребує повторного входу;
`CART_CONTEXT` — налаштування кошика/слота; `ORIGIN` — звірки адреси з
`APP_ORIGIN`; `AI_RATE_LIMIT` — перевірки квоти; `TIMEOUT` — повторної спроби
з конкретнішим запитом. За зміни схеми MCP дійте за [інтеграціями](integrations.md).

Історичний live-прогін описано в [README](../README.md). Він виконаний до
останнього посилення політик; після нього перевірялись локальні тести й
сумісність зі збереженою batch-відповіддю, а не новий наскрізний live-прогін.
